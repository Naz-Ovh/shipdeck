title: Overview
description: Understand Shipdeck and its deployment model in five minutes.
---

Shipdeck builds your app on your computer, sends it to a Linux server over SSH, and runs it
with **systemd or PM2**. Use the terminal UI for daily work, or CLI commands in scripts and
CI. Each deployment has its own release folder, saved settings, and a backup you can roll
back to.

It fits small servers that should run apps without compiling them. Rust, Go, Node.js,
Python, and other stacks work through your own build and setup commands. One deployment can
hold a single app or several apps that switch together.

## Start here

Install Shipdeck on Linux or macOS:

```sh
curl -LsSf https://shipdeck.naz.ovh/install.sh | sh
shipdeck --version
```

From your repository root, create a deployment:

```sh
shipdeck init my-api --preset rust --manager systemd --host prod
```

That writes a **project file** (`shipdeck.yaml`) and a **deploy file** (`deploy.yaml`). The
project file lists the deploys of this repository:

```yaml
deploys:
  production: deploy.yaml
```

The deploy file holds one whole deploy: the server, the release and every app. Edit it to
name:

- Your source folder and local build command.
- The binary or files to send, and any shared data to keep between releases.
- The SSH host and user, server folder, process command, and health check.

```yaml
name: my-api
server:
  ssh: { host: prod, user: deploy }
  dir: /opt/my-api
apps:
  my-api:
    source: .
    files: [dist, package.json, .env]
    process:
      start: node dist/main.js
      env_file: .env
      systemd: {}
    steps:
      health:
        url: http://127.0.0.1:3000/
```

`prod` is an SSH alias with a user and `IdentityFile`. You can instead use an address and
pass `--key`. The SSH user must already exist.

```sh
shipdeck
```

In the terminal UI the deploys of your project file are listed. Select one and press Enter.
`c` connects, `r` opens releases, `D` inspects a release, and `:logs` follows logs. Select an
older release and press Enter to roll back.

The [quickstart](/docs/getting-started/quickstart) has a complete config and the first-deploy
steps on one page.
