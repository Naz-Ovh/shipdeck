---
title: Monorepos
description: Deploy several apps as one release.
---

A deploy can hold several apps. They share one release, one switch and one health gate, and
each app has its own folder in it: `apps/<app>`.

```yaml
name: product
server:
  ssh: { host: prod, user: deploy }
  dir: /opt/product

release:
  files: [package.json, packages]        # shared by every app
  steps:
    backup:
      keep: { open: 3, compressed: 15 }
    health:
      timeout_secs: 20

apps:
  api:
    source: services/api
    files: [services/api/dist]
    process:
      start: node dist/main.js
      env: { PORT: "3000" }
      pm2: {}

  web:
    source: apps/web
    files: [apps/web/dist]
    static: true
```

A `static` app has files and no process. `web` is served from
`/opt/product/current/apps/web/dist`; point your own web server there. One release can mix
process and static apps.

Rules that keep it predictable:

- Apps run in name order, everywhere: commands, restarts and health checks.
- Nothing is copied from `release` into an app. A setting that applies to one app is written
  under that app.
- Process names default to `<name>-<app>`, so two apps in one deploy never share a unit:
  `product-api`, `product-web`.
- A static app in a mixed deploy is skipped by restart; the others still restart.

Deploying only one app is not a mode: it is a deploy with one app. When you want a single app
to move on its own, give it its own deploy file and list both in the root file:

```yaml
root: true
deploys:
  api: deploy/api.yaml
  web: deploy/web.yaml
```

Rollback restores the whole release, apps included, from the settings saved with it. An app
added or removed since then is handled: it is installed or retired as the restored settings
say. See [Releases](/docs/guides/releases).
