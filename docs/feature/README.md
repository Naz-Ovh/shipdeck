# Feature plans

One file per feature: `docs/feature/<name>.md`. A plan holds the thinking
behind a phase or a step in `docs/project-progress.html`, so the tracker can
stay a list of short rows.

A plan has:

- the problem, in a few lines;
- the design, and why not the ones beside it;
- the steps it becomes, by their tracker id (`p1b1`);
- the open questions, each with the answer shipdeck takes until the owner says
  otherwise.

Rules:

- Easy English, like the tracker: short sentences, common words.
- When a decision changes, edit the plan first, then the tracker row and
  `docs/visual/Plan/spec.html`.
- When a step lands, the tracker row is the truth; the plan keeps the why.
